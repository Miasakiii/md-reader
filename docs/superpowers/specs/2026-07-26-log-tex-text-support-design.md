# LOG 与 TeX 纯文本支持设计

**日期：** 2026-07-26

**状态更新：** 2026-07-29

**状态：** 核心实现与本地验证已完成；独立 Windows 安装验收已转由 v1.2.0 封板计划统一追踪

## 背景

本设计启动时，MD Reader 只支持 `.md`、`.markdown` 和 `.txt`。当时文件类型判断分散在前端打开对话框、拖拽、浏览器文件输入、渲染分支、Rust CLI/文件关联处理以及未来文件库计划中。继续直接追加扩展名会扩大重复规则，并使当时基线与尚未实施的文件库/导航重构发生二次返工。

本功能采用独立的“文件类型基础层”：先让当前版本安全支持 `.tex` 和 `.log`，再让现有文件库/导航规格与计划复用同一套策略。本功能不等待文件库、链接导航或回收站功能实施。

## 已确认产品决策

| 扩展名 | 渲染方式 | 可编辑 | 大文件预警 | 新增系统文件关联 |
|---|---|---:|---:|---:|
| `.md` / `.markdown` | Markdown | 是 | 否 | 保持现状 |
| `.txt` | 纯文本 | 是 | 否 | 保持现状 |
| `.tex` | 纯文本源码 | 是 | 否 | 否 |
| `.log` | 纯文本快照 | 否 | 是 | 否 |

补充决策：

- `.tex` 不编译、不生成 PDF、不解析公式或章节，不提供 LaTeX 专用高亮。
- `.log` 不提供实时跟随、自动刷新、分块读取或虚拟滚动。
- `.log` 展示打开时的完整文件快照；达到或超过 10 MiB 时必须在读取内容前提示。
- `.log` 的只读限制同时由前端界面和 Rust 保存命令执行，不能只依赖禁用按钮。
- `.tex` 与 `.log` 可通过打开对话框、拖拽、CLI、最近文件和未来文件库打开，但安装程序不注册这两种扩展名。

## 目标

1. 将运行时文件类型规则收敛到一份共享清单。
2. 支持 `.tex` 的纯文本阅读、搜索、编辑和保存。
3. 支持 `.log` 的只读阅读与搜索，并在大文件完整载入前提示。
4. 所有打开入口使用一致的类型校验、大日志确认和未保存修改保护。
5. 后端拒绝读取不支持的类型，并拒绝覆盖保存 `.log`。
6. 为当前无测试入口的前端建立 Node 内置测试入口，并让 CI 执行 JS 与 Rust 测试。
7. 更新现有文件库/导航规格与计划，使其消费新的类型策略而不是继续写死扩展名。

## 非目标

- 不安装、调用或管理 TeX 发行版。
- 不生成或预览 DVI、PS、PDF。
- 不解析 LaTeX AST、章节、交叉引用或数学公式。
- 不实现日志高亮、过滤器、时间轴、实时监控、`tail -f`、分块读取或虚拟列表。
- 不为 `.tex` 或 `.log` 注册 Windows、macOS 或 Linux 文件关联。
- 不实现文件库、回收站或本地链接导航；仅同步这些未来功能的规格与计划。
- 不在本功能中重写 Markdown 引擎、搜索算法、主题系统或编码选择界面。

## 共享文件类型策略

新增 `shared/document-types.json`，作为运行时支持类型、行为能力和大日志阈值的唯一数据来源。建议结构如下：

```json
{
  "version": 1,
  "largeLogWarningBytes": 10485760,
  "types": {
    "markdown": {
      "extensions": ["md", "markdown"],
      "renderMode": "markdown",
      "editable": true,
      "toc": true,
      "warnWhenLarge": false
    },
    "text": {
      "extensions": ["txt", "tex"],
      "renderMode": "plain",
      "editable": true,
      "toc": false,
      "warnWhenLarge": false
    },
    "log": {
      "extensions": ["log"],
      "renderMode": "plain",
      "editable": false,
      "toc": false,
      "warnWhenLarge": true
    }
  }
}
```

扩展名不包含前导点，比较时统一忽略 ASCII 大小写。路径最后一段没有扩展名、扩展名为空或不在清单中时返回 `unsupported`。

Tauri 的 `fileAssociations` 是安装打包策略，不属于运行时支持清单。它继续只声明当前已有的 `.md`、`.markdown` 和 `.txt`；测试必须防止 `.tex`、`.log` 被意外加入。

## 模块与文件职责

### `shared/document-types.json`

- 保存类型分组、扩展名、渲染模式、编辑能力、TOC 能力和大日志阈值。
- 不保存界面文案、平台路径规则或文件关联配置。

### `src/js/file-types.js`

- 导入并验证共享清单。
- 导出纯函数：扩展名提取、路径分类、可编辑性、渲染模式、TOC 能力、打开对话框过滤器和浏览器 `accept` 值。
- 不访问 DOM，不调用 Tauri，不修改应用状态。

### `src-tauri/src/file_types.rs`

- 通过 `include_str!` 嵌入并解析同一份共享清单。
- 为 Rust 侧提供 `DocumentKind`、路径分类、是否可保存及大日志阈值。
- CLI、拖拽、预检、读取和保存命令只能通过该模块判断类型。
- 清单解析失败时返回稳定的内部错误 `policy_invalid`，不退回任意文件访问。

### `src/js/app.js`

- 保存当前文件的 `kind`、`readOnly`、`sizeBytes` 与 `encoding`。
- 协调打开预检、用户确认、未保存保护、实际读取和界面状态。
- 不再维护独立的扩展名数组或 `isTxtFile()` 特例。

### `src-tauri/src/main.rs`

- 注册预检、读取、保存与最近文件命令。
- 在读取和保存前调用 `file_types` 重新校验。
- 只有实际读取和解码成功后才登记最近文件。

## 命令契约

### `inspect_document(path)`

该命令只做无副作用预检，不读取文件内容、不更新最近文件：

```text
DocumentInspection {
  path,
  kind,
  renderMode,
  readOnly,
  sizeBytes,
  requiresLargeFileConfirmation
}
```

命令依次检查：扩展名受支持、路径存在、路径是普通文件、元数据可读取。目录和其他特殊文件不能作为文档打开。

### `read_file(path, allow_large_log)`

- 再次校验类型、普通文件状态和当前大小。
- `.log` 当前大小达到或超过 10 MiB 且 `allow_large_log=false` 时返回 `large_log_confirmation_required`，不读取内容、不登记最近文件。
- 读取成功后沿用 UTF-8 优先、失败时 GB18030 回退的解码策略。
- 返回 `path`、`content`、`encoding`、`kind`、`renderMode`、`readOnly` 和实际 `sizeBytes`。
- 解码成功后才把路径移到最近文件列表首位。

### `save_file(path, content)`

- 重新按目标路径分类。
- 只允许保存 `.md`、`.markdown`、`.txt` 和 `.tex`。
- `.log` 返回 `readonly_file`；其他格式返回 `unsupported_type`。
- 成功保存统一写入 UTF-8。前端随后把状态栏编码更新为 UTF-8。

## 打开与状态切换流程

所有打开入口汇入同一协调流程：

1. 调用 `inspect_document(path)`。
2. 若是大 `.log`，显示包含文件名、格式化大小及性能风险的“继续 / 取消”确认。
3. 用户取消时立即结束；当前文档、滚动、草稿、导航状态和最近文件均不改变。
4. 当前文档存在未保存修改时，调用统一切换守卫。
5. 守卫返回“保存并继续”时，只有保存真正成功后才能继续；另存为取消等同于取消切换。
6. 守卫返回“放弃修改”时继续；返回“取消”或未知值时终止。
7. 调用 `read_file(path, allow_large_log)`；后端再次校验，处理预检与读取之间的文件变化。
8. 成功后一次性提交新文件状态、渲染内容、标题、状态栏、控件能力和滚动恢复。
9. 失败时保留来源文档，显示结构化错误对应的提示。

若 `.log` 在预检后增长并跨过阈值，`read_file` 仍返回大日志确认错误。前端重新提示，不把该错误误报为普通读取失败。

## 未保存修改保护

本功能提前实现现有文件库/导航规格中已经确认的统一保护接口：

```text
requestDirtySwitchDecision() -> save | discard | cancel
guardDirtyDocumentSwitch({ isDirty, decide, save }) -> boolean
```

约束：

- 打开对话框、拖拽、CLI、文件关联事件、最近文件以及未来文件库和本地链接均复用该守卫。
- 任何目标内容读取和最近文件写入都发生在守卫放行之后。
- `Esc`、关闭对话框、未知返回值、保存失败和另存为取消全部归为 `cancel`。
- 对话框关闭后恢复合理焦点；三个操作均可用键盘到达。
- 新基础功能完成后，旧文件库/导航计划把对应步骤改为前置依赖，不重复实现第二套守卫。

## 渲染与交互

### `.tex`

- 使用纯文本渲染，HTML 转义后保留原始空格、反斜杠和换行。
- 支持全文搜索、编辑模式和保存。
- 不生成文章目录；TOC 按钮禁用并提供说明。
- 状态栏显示格式与编码，例如 `TeX · UTF-8`。

### `.log`

- 使用纯文本渲染并支持全文搜索。
- 只把内容放入阅读区；编辑文本框和隐藏预览区保持为空，避免为大日志额外复制内容。
- 编辑与保存按钮使用原生 `disabled` 状态。
- `Ctrl+E` 和 `Ctrl+S` 不执行切换或保存，改为显示 `LOG 文件以只读模式打开`。
- 状态栏显示 `LOG · <编码> · 只读`。
- 打开新的可编辑文档后恢复编辑、保存和相关快捷键。
- 不监控磁盘变化；外部程序后续追加的内容不会自动出现。

### 纯文本共同规则

- `.txt`、`.tex`、`.log` 均不提供 Markdown TOC。
- Markdown 渲染与 DOMPurify 流程保持不变。
- 搜索仍在当前可见阅读容器中工作。

## 大日志确认

- 阈值固定为 10 MiB，即 `10 * 1024 * 1024` 字节。
- 文件大小等于阈值时即要求确认。
- 提示显示文件名和四舍五入到一位小数的 MiB 大小。
- 提示明确说明应用将完整读取文件，继续可能造成卡顿。
- 不提供“记住选择”、永久关闭预警或可配置阈值。
- 用户确认后没有额外硬上限；本功能不承诺超大文件流畅性。
- 浏览器降级模式使用 `File.size` 执行同一阈值判断。

## 错误模型

前后端使用稳定错误码区分用户动作、类型错误和系统失败：

- `policy_invalid`
- `unsupported_type`
- `missing_file`
- `not_regular_file`
- `metadata_failed`
- `large_log_confirmation_required`
- `decode_failed`
- `read_failed`
- `readonly_file`
- `save_failed`

错误处理原则：

- 除成功提交新文档外，所有错误都保留当前内容、滚动位置、草稿和最近文件列表。
- 从最近文件打开失败时只显示错误，不在本功能中自动删除记录。
- 用户取消大日志确认或未保存切换不使用错误 toast。
- `.log` 保存快捷键被拦截时使用非破坏性状态提示。
- 真正的读写失败使用 `role="alert"`；只读说明和取消后的状态信息使用 `role="status"` 与合适的 `aria-live`。

## 安全与权限

- Rust 是文件类型和保存能力的最终可信边界。
- 读取命令不再接受任意扩展名；保存命令不能覆盖 `.log` 或其他不支持格式。
- 删除未被当前源码使用的 `tauri-plugin-fs` 依赖、插件注册、`fs:*` 权限和全盘 `fs:scope **`。
- 打开对话框继续使用 `tauri-plugin-dialog`，文件内容继续通过受约束的自定义命令读取。
- 不增加 CSP 源、外部进程、shell 命令、网络请求或系统文件关联。
- 更广泛的 CSP 和命令授权重构仍属于现有安全计划，不在本功能中扩张。

## 与文件库和导航计划的衔接

更新现有文件库/导航规格和实施计划：

- 将所有硬编码的 `.md`、`.markdown`、`.txt` 允许列表替换为共享策略调用。
- 本地文档链接未来允许解析 `.tex` 和 `.log`；`.tex` 以可编辑纯文本打开，`.log` 以只读模式打开。
- 当前最近文件和未来文件库可以登记两种新格式。
- 未来回收站命令从共享策略取得受支持扩展名，同时保留其已登记路径、普通文件、非符号链接和二次身份校验约束。
- 把已经由本基础功能完成的类型分类、未保存切换守卫和 fs 权限清理标记为前置依赖。
- 文件库、外链路由、本地链接返回栈和回收站由后续拆分计划分别实施，不纳入本功能验收；2026-07-16 总计划只保留为历史完整设计。

## 测试策略

### JavaScript 单元测试

使用 Node 内置测试运行器覆盖：

- 清单结构验证和扩展名大小写处理。
- `.tex` 为可编辑纯文本、`.log` 为只读纯文本。
- 打开过滤器和浏览器 `accept` 包含五种扩展名。
- Tauri 文件关联不包含 `.tex`、`.log`。
- 纯文本 TOC 能力为 false。
- 大日志取消不读取、不改变状态；确认后才读取。
- 未保存守卫的保存、放弃、取消、保存失败和另存为取消路径。
- 从只读日志切回可编辑文件时恢复控件能力。
- 日志内容不写入隐藏编辑器或预览区。

### Rust 单元测试

覆盖：

- 嵌入清单解析及三类 `DocumentKind`。
- 大小写扩展名、缺失扩展名和不支持类型。
- 缺失文件、目录和普通文件状态。
- 略小于、等于和略大于 10 MiB 的边界。
- 未确认的大日志不读取、不登记最近文件。
- `.log` 保存返回 `readonly_file`，目标内容和修改时间不变。
- `.tex` UTF-8 与 GB18030 解码。
- `.tex` 保存结果为 UTF-8。
- 只有成功读取才登记最近文件。

所有 Rust 测试使用系统临时目录和进程唯一文件名，不读取、覆盖、移动或删除用户文件。

### 构建与 CI

本功能为 `package.json` 增加 Node 测试入口。当前 Checks workflow 使用 Node.js 24 与 `npm ci`，并执行：

- `npm test`
- `npm run build`
- `cargo fmt --manifest-path src-tauri/Cargo.toml -- --check`
- `cargo test --manifest-path src-tauri/Cargo.toml --locked`
- `cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets --locked -- -D warnings`

任何一步失败都会使 Checks workflow 失败；仓库可通过分支保护将其作为合并门禁。

### 桌面交互验证

- 通过打开对话框、拖拽和 CLI 分别打开 `.tex` 与 `.log`。
- 验证 `.tex` 的反斜杠、缩进和换行无损，编辑保存后文件为 UTF-8。
- 验证 `.log` 的编辑、保存按钮和快捷键均不能修改原文件；比较验证前后的哈希与修改时间。
- 使用略小于、等于和大于 10 MiB 的临时日志验证预警边界、取消和继续。
- 在脏文档状态下分别验证保存、放弃和取消后再打开日志。
- 检查大日志内容只存在于阅读区。
- 打开其他可编辑文档后确认控件恢复。
- 检查打包配置未新增 `.tex`、`.log` 文件关联。
- 验证结束后只删除本轮创建的临时夹具，不清理用户目录或系统回收站。

## 验收标准

1. `.tex` 可作为纯文本完整阅读、搜索、编辑和保存。
2. `.log` 可阅读和搜索，但任何前端或后端入口都不能覆盖保存。
3. 达到或超过 10 MiB 的日志在内容读取前提示；取消不改变当前工作。
4. 所有现有和未来文档切换入口共享同一未保存修改保护。
5. JS 与 Rust 消费同一份运行时文件类型清单，没有散落的扩展名数组。
6. `.tex`、`.log` 不进入系统文件关联。
7. 不增加文件系统权限，并移除未使用的全盘 fs 权限。
8. JavaScript 测试、Rust 测试、生产构建和关键桌面交互验证全部通过。
9. README、CHANGELOG 及现有文件库/导航设计与新格式保持一致。
10. 未实施的实时日志、TeX 编译和文件库功能没有被文案暗示为已支持。
