## 背景

MD Reader 当前只在欢迎页展示最近 8 个文件，阅读时没有文件侧栏。最近文件由 Rust 后端写入 `recent.json`，最多保存 20 条。Markdown 正文目前没有统一的链接路由：正文点击委托只处理“复制代码”，因此网页链接会按 WebView 默认行为在应用内导航。

当前应用图标虽然画面内有圆角卡片，但源图和派生 PNG 的四角像素仍完全不透明，系统显示时仍可能呈现方形底。设计启动时记录的部分 Rust/JavaScript 与 README 基线问题已经清理；未引用 CSS、重复图标源和透明圆角等剩余项仍需在实施前重新做引用与像素审计。

截至 2026-07-26，项目已先行交付 LOG/TeX 文档基础：运行时通过 `shared/document-types.json` 支持 `.md`、`.markdown`、`.txt`、`.tex`、`.log`；`.tex` 是可编辑纯文本，`.log` 是可搜索的只读一次性快照，达到或超过 10 MiB 时读取前确认。`src/js/file-types.js` 与 `src-tauri/src/file_types.rs` 分别校验并消费同一策略，`src/js/document-session.js` 已提供未保存文档切换守卫。Tauri 前端文件系统插件与 `fs:*` 权限也已移除。上述基础不代表本规格的文件库、链接返回或回收站功能已经实现。

## 目标

1. 新增阅读时可展开的持久化文件目录侧栏。
2. 支持从目录中移除记录，或经二次确认将原文件移入系统回收站。
3. 将网页链接交给系统默认程序打开，并为文档内锚点和本地文档链接提供明确、可返回的应用内行为。

- 不包含提交、推送或发布版本的工作。

## 总体架构

采用“轻量文件库”而非真实文件系统树：成功打开过的受支持文件自动进入持久化列表，列表顺序即最近使用顺序。Rust 后端负责存储、路径校验与回收站操作；前端负责侧栏、菜单、链接路由和导航历史。

文档类型边界不属于文件库或导航模块自行维护的产品规则。`shared/document-types.json` 是运行时格式与能力的唯一清单；任何新增格式先修改该策略及其前后端校验测试，后续模块自动继承，不再同步多份扩展名正则或 `match` 列表。系统文件关联是独立的产品边界，继续只在 Tauri 配置中注册 `.md`、`.markdown`、`.txt`，不得因运行时支持 `.tex` / `.log` 而自动扩大。

新增模块边界：

- `src/js/file-types.js`（已交付基础）：共享策略的前端校验、路径分类与打开/保存过滤器。
- `src/js/document-session.js`（已交付基础）：大型日志确认、未保存修改守卫和文档打开协调；后续切换入口复用它，不复制守卫。
- `src/js/file-library.js`：文件目录视图、当前项选择、右键菜单和关闭行为；受支持类型判断调用 `file-types.js`。
- `src/js/navigation.js`：链接分类、本地路径解析和文件导航历史；本地目标合法性调用 `file-types.js`。
- `src/js/app.js`：保留应用状态与模块协调，不再承载新增功能的全部实现。
- `src-tauri/src/file_types.rs`（已交付基础）：共享策略的后端校验、文档能力与路径分类。
- `src-tauri/src/library.rs`：文件库持久化、登记/移除、路径安全校验和回收站调用；登记、状态检查与回收站类型判断必须调用 `file_types.rs`。
- `src-tauri/src/main.rs`：保留文件读写、阅读进度、应用生命周期和命令注册。

文件侧栏和现有文章目录侧栏共用左侧区域并互斥显示，避免同时挤压阅读区。

## 文件目录体验

### 打开与展示

- 工具栏新增“文件目录”按钮，阅读、编辑和欢迎状态均可展开。
- 侧栏列出全部已登记文件；最近成功打开的文件排在最前。
- 文件库接受共享策略当前支持的五种运行时格式，并随策略演进；不得在文件库中另写后缀清单。
- 每项显示文件名和完整路径，当前打开文件高亮。
- 单击条目使用现有阅读器打开文件。
- 欢迎页继续展示文件库前 8 项，避免移除现有快速入口。
- 打开文件目录时自动关闭文章目录；打开文章目录时自动关闭文件目录。

### 右键菜单

在文件项上右键，或聚焦条目后按菜单键/`Shift+F10`，显示自定义菜单：

1. **移出文件目录**：只删除文件库记录，不修改磁盘文件，也不清除其阅读进度。若该文件当前已打开，内容保持打开，但侧栏不再显示它。
2. **移到回收站…**：先显示系统确认框。确认文字包含文件名，并明确文件可从系统回收站恢复；若当前文档有未保存修改，额外提示这些修改会丢失。

回收站操作成功后才移除文件库记录并清除该文件的阅读进度。若被移除的是当前文件，应用清空编辑状态并回到欢迎页。操作失败时保留文件库记录和当前页面，并显示具体错误。

菜单在选择操作、点击菜单外、窗口失焦、滚动侧栏或按 `Esc` 时关闭。菜单位置被限制在可视窗口内，不允许溢出底部或右侧。

### 持久化与迁移

- 新文件库使用 `library.json` 保存路径字符串数组，不设置 20 条上限。
- 首次升级且 `library.json` 不存在时，从现有 `recent.json` 导入已有条目；旧文件保留用于版本回退。
- 只有文件读取并解码成功后才登记路径。
- Windows 下去重时忽略路径大小写；其他平台保留平台原有路径语义。
- 读取失败后若确认文件已不存在，前端提示并移除失效记录；权限、编码或临时设备错误不会自动删除记录。

## 链接与返回行为

正文阅读区和编辑预览区共用同一链接路由：

### 网页与系统链接

- `http:`、`https:` 和 `mailto:` 由 Tauri 的系统打开能力交给默认浏览器或邮件程序。
- 点击时阻止 WebView 默认导航，因此 MD Reader 的当前文件、滚动位置和编辑状态保持不变。
- 浏览器预览模式使用带 `noopener,noreferrer` 的新窗口作为降级行为。
- 其他协议默认拦截并显示提示，不传给系统执行。

### 文档内锚点

- `#heading` 链接只在当前阅读容器内滚动到对应标题。
- 不改变 WebView 页面地址，也不创建文件导航历史。
- 找不到目标时不离开当前页面，并显示简短提示。

### 本地文档链接

- 相对或绝对、且由 `src/js/file-types.js` 判定为受支持文档的链接在 MD Reader 内打开；当前策略因此涵盖 `.md`、`.markdown`、`.txt`、`.tex`、`.log`。
- 相对路径以当前文件所在目录为基准解析，并支持链接尾部的标题片段。
- 打开前记录当前文件路径和滚动位置；成功打开后将记录压入导航栈。
- 导航栈非空时，工具栏显示紧凑的“返回”按钮。返回会重新打开上一文件并恢复原滚动位置，且不会再次向栈内压入相同记录。
- 手动从文件目录、打开对话框或拖拽切换文件时清空链接导航栈，避免“返回”含义不明确。
- 当前编辑内容有未保存修改时，任何文档切换入口（本地链接、返回、手动打开、拖拽、命令行或文件关联）都复用已交付的 `document-session.js` 守卫，先提供“保存并继续 / 放弃修改 / 取消”；保存失败或取消时不读取目标、不改变当前内容或导航栈。`.log` 本身只读，但从可编辑文档切换到日志时仍必须经过同一守卫。
- 解析结果不是受支持文件类型、目标不存在或读取失败时，保持当前文件不变并显示错误。

## 后端安全边界

回收站命令必须同时满足以下条件：

1. 请求路径与文件库中的已登记条目匹配。
2. 路径当前存在且是普通文件。
3. `src-tauri/src/file_types.rs::classify_path` 按共享策略将路径判定为受支持文档；比较时忽略扩展名大小写，不在 `library.rs` 重复硬编码后缀。
4. 前端已经取得用户确认；后端仍独立执行路径校验，不能依赖前端正确性。

实际删除使用跨平台系统回收站能力，不调用永久删除 API。只有回收站调用成功后才更新 `library.json` 和 `progress.json`。外部链接能力仅放行 `http`、`https` 与 `mailto`，并维持现有 CSP 和 DOMPurify 过滤。前端不重新获得 Tauri 文件系统权限；文件库、状态与回收站操作全部通过收窄的 Rust 命令边界完成。

配置写入采用同目录临时文件与可恢复备份；所有存在性判断传播权限、设备和其他 I/O 错误，只有明确 NotFound 才视为空数据。`tmp -> target` 是唯一提交点，目标与备份都不存在时的孤立 tmp 视为未提交写入并清理，不能提升为正式配置。应用启用单实例并在进程内串行化配置命令，避免多个写入者争用同一文件。

回收站操作用只记录路径与阶段的增量事务日志。事务日志落盘后、实际调用系统回收站前，后端再次确认路径仍是普通非符号链接并比较跨平台文件身份；复核失败立即取消，文件库和进度不变。系统回收站调用成功后若元数据收尾失败，前端必须明确告知“原文件已移入回收站、记录清理待自动恢复”，不能把它误报成原文件仍在的普通失败；下次文件库操作会幂等补齐记录和进度清理。

## 错误处理

- 文件库读取失败：保留当前文档，侧栏显示可重试的错误状态。
- 移出目录写入失败：恢复条目并显示错误，不做乐观成功提示。
- 回收站取消：不改变任何状态。
- 回收站调用前校验失败或系统回收站调用失败：保留条目、当前文档和阅读进度，显示系统返回的原因。
- 系统回收站已成功但元数据收尾失败：立即按“文件已移走”更新当前页面，显示可恢复警告，并保留事务日志供下次自动补齐清理。
- 系统浏览器打开失败：当前文档不变并显示链接打开失败提示。
- 未保存修改保护选择取消，或选择保存但保存失败/另存为被取消：终止文档切换，当前内容、滚动位置和导航栈保持不变。
- 本地链接打开失败：不压入导航栈，当前文档和滚动位置保持不变。
- 返回目标已丢失：移除该条无效历史，提示用户，并继续允许返回更早记录。

## 验收标准

以下条目是历史完整愿景的总验收集合；拆分后的各里程碑只接受其独立计划中明确列出的子集。

- 阅读时可展开文件目录，且与文章目录互斥。
- 已打开文件自动进入文件库，顺序和当前项状态正确。
- 文件库、本地链接与回收站共享前后端文档类型策略，当前五种运行时格式行为一致；系统文件关联仍仅为 `.md` / `.markdown` / `.txt`。
- “移出文件目录”绝不触碰原文件。
